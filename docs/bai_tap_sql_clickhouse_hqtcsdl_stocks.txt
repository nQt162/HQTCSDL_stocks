Bộ bài tập SQL ClickHouse cho dự án HQTCSDL Stocks
Tài liệu này tổng hợp các câu lệnh SQL/ClickHouse đang xuất hiện trong dự án và chuyển chúng thành bộ đề luyện tập cho nhóm.
Đề bài tổng quát
Bạn đang xây dựng hệ thống dữ liệu chứng khoán gồm dữ liệu OHLCV, thông tin symbol/ngành, feature engineering, data mart cho nhiều mô hình dự đoán, dashboard insight và kiểm tra chất lượng dữ liệu. Hãy dùng ClickHouse để tạo bảng, nạp/kiểm tra dữ liệu, truy vấn phân tích và thiết kế mart phục vụ dashboard.
Các SQL bên dưới dùng tên bảng theo code hiện tại: stock.stock_prices, stock.stock_symbols, stock.symbol_sector_encoding, stock.features_all, stock_mart.*, stock_mart_model5_risk_prediction.*. Nếu môi trường dùng schema đề xuất trong docs/clickhouse_schema_proposal.sql thì đổi database/table tương ứng.
Nguồn SQL đã rà trong repo
- docs/clickhouse_schema_proposal.sql: đề xuất schema staging, DW, mart, audit.
- connect_clickhouse/*.py: tạo database/bảng stock, upload giá, symbol, features_all.
- models/model1/src/data_loader.py và marts.py: đọc features_all, tạo mart dự báo giá, top expected return, backtest, metrics, insights.
- models/model2/src/*.py và streamlit_model2_demo.py: đọc features_all, truy vấn symbol/ngày, tạo mart future_return_5d.
- models/model3/src/data_loader.py và test.py: đọc features_all và batch theo ngày cho BUY/HOLD/SELL.
- models/model4/*.py: lọc top 100 mã benchmark, đọc stock_prices, upload và verify prediction outperform.
- models/model5/*.py: risk features, risk predictions, risk mart, dashboard risk view, kiểm tra/alter schema.
- main_web.py: dashboard tổng quan, lookup OHLCV, feature preview, data mart preview, insight, data quality.
- upload_all.py: upload tổng hợp, tạo bảng động, metadata quan hệ và key bảng.

===============================
A. Kết nối và metadata hệ thống
===============================
Bài 01. Kiểm tra phiên bản ClickHouse
Đề bài: Viết truy vấn kiểm tra server ClickHouse đang kết nối là phiên bản nào.
Ý nghĩa: Dùng ở bước smoke test để biết client đã kết nối đúng ClickHouse trước khi nạp dữ liệu hoặc chạy pipeline.
Nguồn trong dự án: connect_clickhouse/test_clickhouse_connection.py
SQL mẫu:
SELECT version();
Bài 02. Kiểm tra một bảng có tồn tại hay không
Đề bài: Kiểm tra bảng features_all có tồn tại trong database stock hay chưa.
Ý nghĩa: Dùng trước khi dashboard hoặc pipeline đọc bảng để tránh lỗi truy vấn vào bảng chưa được tạo.
Nguồn trong dự án: main_web.py, models/model5/create_risk_mart.py
SQL mẫu:
SELECT count() AS cnt
FROM system.tables
WHERE database = 'stock'
  AND name = 'features_all';
Bài 03. Xem danh sách cột của một bảng
Đề bài: Lấy danh sách cột của bảng stock.features_all theo đúng thứ tự schema.
Ý nghĩa: Dùng để preview schema trong trang Data Mart và để kiểm tra thiếu cột trước khi upload thêm dữ liệu.
Nguồn trong dự án: main_web.py, models/model5/upload_outputs_to_clickhouse.py
SQL mẫu:
SELECT name
FROM system.columns
WHERE database = 'stock'
  AND table = 'features_all'
ORDER BY position;
Bài 04. Liệt kê các bảng mart/warehouse
Đề bài: Liệt kê bảng trong các database stock, stock_mart và stock_mart_model5_risk_prediction.
Ý nghĩa: Phục vụ trang Data Mart: cho người dùng thấy hệ thống hiện có những bảng phân tích nào, số dòng và dung lượng bao nhiêu.
Nguồn trong dự án: main_web.py
SQL mẫu:
SELECT
    database,
    name AS table_name,
    total_rows,
    total_bytes
FROM system.tables
WHERE database IN ('stock', 'stock_mart', 'stock_mart_model5_risk_prediction')
ORDER BY database, name;

Bài 06. Tạo bảng giá OHLCV

Ý nghĩa: Đây là bảng nguồn quan trọng nhất cho dashboard, feature engineering và một số model benchmark.
Nguồn trong dự án: connect_clickhouse/load_prices_to_click_house.py

CREATE TABLE IF NOT EXISTS stock.stock_prices
(
    symbol String,
    date DateTime,
    open Float64,
    high Float64,
    low Float64,
    close Float64,
    volume Float64
)
ENGINE = MergeTree
ORDER BY (symbol, date);
Bài 07. Xóa dữ liệu cũ trước khi upload lại giá

Bài 30. Hiệu suất trung bình theo ngành
Đề bài: Join features_all với stock_symbols để tính return_5d trung bình theo sector.
Ý nghĩa: Cho biết ngành nào có hiệu suất tốt nhất trong giai đoạn gần nhất.
Nguồn trong dự án: main_web.py
SQL mẫu:
SELECT
    coalesce(s.sector, 'UNKNOWN') AS sector,
    avg(f.return_5d) AS avg_return_5d,
    count() AS stock_count
FROM stock.features_all AS f
LEFT JOIN stock.stock_symbols AS s
    ON f.symbol = s.symbol
WHERE toDate(f.trading_date) = (
    SELECT max(toDate(trading_date))
    FROM stock.features_all
)
  AND f.return_5d IS NOT NULL
GROUP BY sector
ORDER BY avg_return_5d DESC
LIMIT 15;
Bài 31. Cổ phiếu biến động mạnh nhất
Đề bài: Lấy 10 mã có volatility_20d cao nhất, ưu tiên thêm abs(return_5d).
Ý nghĩa: Tìm các mã rủi ro/biến động mạnh để đưa vào trang Insight hoặc Risk.
Nguồn trong dự án: main_web.py
SQL mẫu:
SELECT
    symbol,
    close,
    volatility_20d,
    abs(return_5d) AS abs_return_5d
FROM stock.features_all
WHERE toDate(trading_date) = (
    SELECT max(toDate(trading_date))
    FROM stock.features_all
)
ORDER BY volatility_20d DESC, abs_return_5d DESC
LIMIT 10;

Bài 32. Tổng hợp lỗi chất lượng dữ liệu OHLCV
Đề bài: Đếm tổng dòng, số mã, khoảng ngày và các lỗi giá/volume/OHLC/trùng khóa.
Ý nghĩa: Trang Chất lượng dữ liệu dùng truy vấn này để chứng minh dữ liệu đã được kiểm soát trước khi train model.
Nguồn trong dự án: main_web.py
SQL mẫu:
SELECT
    count() AS total_rows,
    countDistinct(symbol) AS total_symbols,
    min(toDate(date)) AS min_date,
    max(toDate(date)) AS max_date,
    countIf(open <= 0 OR high <= 0 OR low <= 0 OR close <= 0) AS non_positive_prices,
    countIf(volume < 0) AS negative_volume,
    countIf(
        high < low
        OR high < open
        OR high < close
        OR low > open
        OR low > close
    ) AS invalid_ohlc,
    count() - uniqExact(tuple(symbol, date)) AS duplicate_symbol_date
FROM stock.stock_prices;
Bài 33. Liệt kê dòng trùng symbol-date
Đề bài: Tìm các cặp symbol-date có nhiều hơn một bản ghi.
Ý nghĩa: Bài tập mở rộng từ metric duplicate_symbol_date để nhóm biết cách điều tra lỗi trùng khóa.
Nguồn trong dự án: Suy ra từ main_web.py quality check
SQL mẫu:
SELECT
    symbol,
    toDate(date) AS trading_date,
    count() AS row_count
FROM stock.stock_prices
GROUP BY symbol, trading_date
HAVING row_count > 1
ORDER BY row_count DESC, symbol, trading_date;

CREATE OR REPLACE VIEW stock.mart_risk_alerts AS
SELECT
    p.prediction_date AS prediction_date,
    p.target_date AS target_date,
    p.symbol AS symbol,
    f.open AS open,
    f.high AS high,
    f.low AS low,
    f.close AS close,
    f.volume AS volume,
    s.company_name AS company_name,
    f.return_5d AS return_5d,
    f.drawdown_20d AS drawdown_20d,
    f.volatility_5d AS volatility_5d,
    f.volume_ratio_5_20 AS volume_ratio_5_20,
    f.daily_range AS daily_range,
    f.close_position AS close_position,
    p.risk_probability AS risk_probability,
    p.risk_label AS risk_label,
    p.model_name AS model_name
FROM stock.dw_stock_risk_predictions AS p
LEFT JOIN stock.dw_stock_risk_features AS f
    ON p.symbol = f.symbol
    AND p.prediction_date = f.trading_date
LEFT JOIN stock.dw_stock_symbols AS s
    ON p.symbol = s.symbol;

    completed_models Array(String),
    error_message Nullable(String)
)
ENGINE = MergeTree
ORDER BY (workflow_name, started_at, pipeline_run_id);
Bài 59. Tạo bảng audit data_quality_summary
Đề bài: Tạo bảng lưu kết quả kiểm tra chất lượng dữ liệu theo từng pipeline_run_id.
Ý nghĩa: Khi data quality chạy tự động, bảng này lưu check_name, bad_rows, total_rows và bad_ratio để theo dõi lịch sử.
Nguồn trong dự án: docs/clickhouse_schema_proposal.sql
SQL mẫu:
CREATE TABLE IF NOT EXISTS stock_audit.data_quality_summary
(
    pipeline_run_id UUID,
    check_name String,
    status String,
    bad_rows Nullable(UInt64),
    total_rows Nullable(UInt64),
    bad_ratio Nullable(Float64),
    report_file Nullable(String),
    created_at DateTime DEFAULT now()
)
ENGINE = MergeTree
ORDER BY (pipeline_run_id, check_name);
